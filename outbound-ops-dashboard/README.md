# Outbound Ops Dashboard

A real-time operations dashboard for a warehouse **outbound / shipping** department of an e-commerce operation.
It tracks picker productivity, order pipeline per carrier, hourly output, truck-load projection and daily shift planning, in one responsive, dark/light-themed web app.

> **Demo build:** every number, name and carrier you see comes from a local, fictional mock data file.
> See [Confidentiality & Data Protection](#-confidentiality--data-protection).

---

## 🔒 Confidentiality & Data Protection

This project started as an internal tool built for a real logistics operation. To publish it as a portfolio piece **without exposing any confidential information**, the codebase was refactored:

- **All real data was removed.** Collaborator names, carrier names, order volumes, history and brand assets were replaced by **fictional, randomly generated mock data** (`src/data/mockData.json`, generated by `scripts/generate-mock-data.py`).
- **All internal integrations were disconnected.** The original connections to the company's WMS (Warehouse Management System) panels, internal servers, the cloud database, realtime sync and scheduled server-side collectors were **removed from this repository**.
- **No secrets, keys or internal URLs are included.** The only configurable value is an optional public API base URL, documented in `.env.example`. A real `.env` is git-ignored.
- **Business rules were kept, data was not.** The parsing, classification, aggregation and projection logic is the original work; only its inputs were replaced.

Any resemblance of the mock data to real people, companies or operations is coincidental. This repository is published in compliance with the confidentiality (NDA) obligations of the original engagement.

## ✨ Features

| Tab | What it does |
| --- | --- |
| **Dashboard** | KPIs (total orders, team average per hour, top performer, people below target), per-collaborator ranking with stacked HUB / third-party bars, participation donut, filters (user, top N, hide users, search) and a **date-range history** selector that aggregates several days. |
| **Outbound Management** | Shift performance table by time slot (day + night shift): planned vs. accumulated vs. achieved, % of target, orders per person-hour, with an **edit mode** that overrides only the fields you change. |
| **Correlation Engine** | Estimates which carrier group (HUB vs. third-party) each collaborator is working on by matching order deltas between snapshots (`src/lib/correlation-engine.ts`). |
| **Projection** | Daily volume projection, truck occupancy (bags per truck), editable carrier share percentages and capacity alerts. |
| **Operational Filter** | Orders per carrier and pipeline stage (awaiting wave, awaiting picking, picked, invoiced with/without load), split by Normal / Personalized / Hive / Express, with **expandable rows**, group toggles, sticky headers and per-carrier color styling. |
| **Hourly Productivity** | Collaborator × hour matrix (08h-23h) with totals, sorting and daily history. |
| **Team POD** | Shift scale: leadership, support roles, carrier assignment, lunch breaks, with **A4 landscape print layout**. |
| **Cost per Piece** | Local CSV upload to compute transfer cost per piece by carrier group. |

Other details: auto-refresh every 30 s (simulated live feed in demo mode), dark/light theme, Brazilian number/date formatting, print-optimized views.

## 🚀 Running Locally

**Requirements:** [Bun](https://bun.sh) 1.1+ (or Node.js 20+ with npm).

```bash
# 1. Clone
git clone https://github.com/kaynan01/outbound-ops-dashboard.git
cd outbound-ops-dashboard

# 2. Install dependencies
bun install          # or: npm install

# 3. (Optional) environment variables
cp .env.example .env # works out of the box with mock data

# 4. Start the dev server
bun run dev          # or: npm run dev
```

Open the URL printed in the terminal (usually `http://localhost:8080` or `http://localhost:5173`).

Other scripts:

```bash
bun run build     # production build
bun run preview   # preview the production build
bun run lint      # eslint
```

### Regenerating the mock data

```bash
python3 scripts/generate-mock-data.py
```

The script uses a fixed random seed, so the output is reproducible. History dates are anchored to "today" at runtime, so the date-range selector always has the last 30 days available.

### Plugging in a real API (optional)

Set `VITE_API_BASE_URL` in `.env` to an HTTPS API you own that returns the same raw JSON shape as the `productivityPanel`, `operationalPanel` and `hourlyPanel` arrays in `mockData.json`. History, correlation and shift data remain local in this public version.
